# AIKA 动态知识库与多 Agent 协作需求说明

- 文档状态：需求草案，供产品、设计与开发评审
- 日期：2026-11-26
- 适用项目：AIKA，面向 AI 算力产业链的证据驱动投研系统
- 参考方向：腾讯 Marvis 的角色化协作交互、ima 的多来源知识管理；本文为 AIKA 的独立需求设计，不假定复现其内部实现。

## 1. 背景与问题

AIKA 已具备产业链问答、原文检索、结构化证据、知识图谱、研究任务和引用展示等能力。现有数据准备与索引构建主要通过本地数据和脚本完成；MCP 服务目前是只读的。Web 提供对话和独立的 Agent 任务页面，但尚未形成面向用户的知识库增删闭环，也没有在同一对话中以投研角色展示协作。

用户需要在阅读和研究过程中随手沉淀资料，并在之后的提问中检索、引用；同时希望看到不同专业角色在同一个会话中承担什么工作。

## 2. 目标与范围

### 2.1 产品目标

1. 用户通过自然语言、粘贴文本、上传文档或提供网址管理知识；资料完成索引后可用于检索和带引用的回答。
2. 用户在同一会话中看到实际参与任务的投研 Agent、工作状态、结果和证据，复杂任务由主 Agent 汇总。
3. 保持 AI 算力产业链投研定位，先提供内置角色，再逐步开放有边界的投研模板配置。
4. 保留现有证据驱动问答和研究能力，逐步接入新增资料，不要求首次发布就自动构建知识图谱。

### 2.2 首期范围（MVP）

- 单用户、本地可信环境：一个默认知识库，支持文本、PDF 和公开网页；支持文档列表、查看、删除、重新处理及基于知识库问答。
- 同一会话内展示首席研究员、资料管理员、研报分析师、产业研究员、证据审查员；按任务实际需要调用，不要求每次全员参与。
- 新知识先进入原文检索链路；结构化 Claim 和图谱的自动生成不作为首期入库成功条件。
- 首期不承诺外网或手机访问；后续实现身份认证、授权、加密传输等能力并部署后，才能支持远程访问。

### 2.3 暂不纳入首期

微信/邮件自动接入、扫描件 OCR、音视频解析、批量文件夹同步、定时网页更新、多人共享和权限管理、开放式 Agent 市场、用户任意定义工具或代码执行。网页抓取不保证支持登录、付费或反爬页面。

## 3. 目标用户与典型场景

| 用户 | 需求 | 预期结果 |
| --- | --- | --- |
| 产业研究者 | 随手收录算力产业资讯和研报，后续围绕公司、技术或风险提问。 | 不用手工运行索引脚本；回答可回看原文。 |
| 投资研究人员 | 比较多份资料中的业务进展和风险，识别口径不一致。 | 看到角色分工、引用及证据缺口。 |
| 项目使用者/开发者 | 通过对话管理个人研究资料，并了解任务运行状态。 | 知道入库是否完成、哪个角色执行以及失败原因。 |

## 4. 功能一：动态知识库

### 4.1 内容收录

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| KB-01 | 用户可粘贴文本并说“把这段信息存到知识库”，系统将内容作为一份资料保存；允许填写或自动生成标题。 | P0 |
| KB-02 | 用户可上传 PDF 并通过对话要求收录。系统解析可提取的文本并保留文件和可用的页码信息。 | P0 |
| KB-03 | 用户可提交公开网页 URL 并要求收录。系统获取并解析正文，保存来源 URL、抓取时间和正文快照。 | P0 |
| KB-04 | 入库操作返回资料标识、标题、当前状态；资料不存在、解析为空或抓取失败时明确报错和重试入口，不得报告成功。 | P0 |
| KB-05 | 用户可查看资料列表及详情，包括类型、来源、添加时间、处理状态、失败原因和可用原文。 | P0 |
| KB-06 | 同一内容重复提交时提示已有资料，由用户选择保留原资料或创建新版本；重复检测至少依据内容摘要，URL 可作为辅助。 | P1 |
| KB-07 | 提供资料标签、主题和公司等元数据供用户查看和编辑；自动提取结果允许修正。 | P1 |

PDF 扫描件如无法提取文本，应提示需 OCR 或其他输入方式，不应标记为可检索。网页正文与原站可能不同步，应显示抓取时间；需要登录或无法访问时应保留明确错误信息。

### 4.2 处理、更新和状态

- 新资料经过保存、解析、分块、关键词索引及在启用时的向量索引。以文档为单位增量处理，不因新增单份资料而全量重建整个知识库。
- 用户可看到 `已接收 → 处理中 → 可检索 / 失败`。只有首期配置要求的检索索引完成后才显示“可检索”；语义索引未配置或失败时，应明确标注检索能力和降级状态，不能暗示所有索引均已完成。
- 支持失败后重新处理。任务重试不得产生重复资料或重复文本块；更新或重新抓取时保留版本和时间信息，并在新版本可用后切换检索版本。
- URL 不自动持续同步；首期通过用户主动重新处理更新。自动定时同步留待后续。
- 来源记录至少包含资料 ID、标题、类型、原始来源或文件名、添加时间、版本、状态、内容摘要；文本块保留所属资料及页码或位置等可用定位信息。

### 4.3 检索与问答

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| KB-08 | 用户提问时，已完成索引的资料可被现有原文 RAG 检索；系统结合相关证据生成回答。 | P0 |
| KB-09 | 引用显示资料标题和可用位置，并能打开资料或查看对应原文；有来源网址时可跳转。 | P0 |
| KB-10 | 资料不足、处理未完成或存在冲突时，明确说明，避免将未获支持的推断表述为事实。 | P0 |
| KB-11 | 正常问答自动检索可用知识库资料，并结合其他研究证据生成带引用的回答；不提供单独的“仅知识库”模式。 | P0 |

首期“可检索”指资料进入原文检索，不保证新资料自动进入既有结构化 Claim 或知识图谱，也不保证每次回答都一定召回；回答需要保留原有证据检查逻辑。

### 4.4 删除与更新

- 用户可从列表或自然语言指定资料删除。若描述对应多份资料，先展示候选项让用户明确选择；删除前展示资料标题和影响范围并要求确认。
- 确认后资料立即退出新的检索结果；删除原文、文本块、关键词及向量索引。相关后台处理任务应取消或阻止其重新写入，清理失败要显示状态并可重试。
- 历史对话保留既有回答，但已删除的引用标为“来源已删除”，不再提供被删原文。日志和备份的清理策略在实施时明确，不能把退出检索等同于所有副本已物理擦除。
- 如未来支持由该资料生成 Claim 或图谱关系，必须记录来源关联；删除资料时解除关联，只有没有其他来源支持的派生内容才失效或删除。首期不要求自动抽取这些派生内容。
- 已完成的删除不能静默恢复；如需恢复，用户重新提供资料。

## 5. 功能二：同一会话中的多 Agent 协作

### 5.1 角色设计

| 角色 | 职责 | 典型输入与输出 |
| --- | --- | --- |
| 首席研究员 | 理解用户意图、决定任务分工、汇总结果；简单任务可直接处理。 | “比较两家公司” → 研究计划和最终回答。 |
| 资料管理员 | 接收并管理资料，反馈入库、删除及处理状态。 | “收录这个网址” → 资料卡与真实状态。 |
| 研报分析师 | 在可用资料中检索、阅读、提取观点与数据，提供引用。 | “总结这份研报” → 核心观点与原文位置。 |
| 产业研究员 | 结合资料和现有产业链、公司关系能力进行分析和比较。 | “分析液冷布局” → 比较维度、结论和依据。 |
| 证据审查员 | 检查关键结论的依据、数据口径、冲突和资料缺口。 | “指出风险” → 已核查内容与未能确认的部分。 |

这些是面向用户的职责，可组合现有检索、图谱和证据检查能力；不要求每个角色都拥有独立模型或进程。角色消息必须对应真实执行的步骤或结果，不得通过切换头像虚构协作。

### 5.2 调度与会话体验

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| AG-01 | 用户只需在同一输入框提交任务；系统识别意图并调用适当角色。简单任务可只调用一个角色。 | P0 |
| AG-02 | 同一会话按事件发生顺序展示角色头像、名称、职责、状态和结果；并行任务可同时显示，完成顺序按实际事件更新。 | P0 |
| AG-03 | 状态至少包括等待、执行中、已完成、失败；必要时显示跳过或降级，并给出可理解的原因。 | P0 |
| AG-04 | 角色输出可展开查看简要工作结果、关联资料和引用；复杂研究由首席研究员汇总，避免把中间结果误认为最终结论。 | P0 |
| AG-05 | 页面刷新或重新打开会话后，已保存的角色消息与最终结果仍可查看；中断时显示已知状态，不伪称完成。 | P0 |
| AG-06 | 系统支持用户指定某个内置角色处理任务；不适用时说明并建议合适角色。 | P1 |
| AG-07 | 用户可通过角色资料卡了解其职责和可用能力。 | P1 |

**示例 A：入库。** 用户提交 URL → 资料管理员显示“正在获取网页” → 页面显示“处理中” → 索引完成后显示“可检索”及资料卡；获取失败则展示失败原因和重试入口。

**示例 B：公司比较。** 用户提出比较问题 → 首席研究员说明分析方向 → 研报分析师与产业研究员按实际任务运行 → 证据审查员标注可核查的结论和缺口 → 首席研究员输出带引用的综合回答。某个角色失败时，展示失败并说明最终答案受限范围。

### 5.3 用户自定义角色

首期使用内置角色，不提供任意 Agent 创建。后续优先支持配置角色的显示名称、头像、关注主题、回答偏好和知识范围；再根据需求提供“液冷研究员”“光模块研究员”等投研模板。模板复用受控工具和证据规则，不允许用户通过名称或提示词绕过权限与来源要求。任意工具接入和通用 Agent 平台不在当前范围。

## 6. 交互与页面

### 6.1 对话区

- 沿用单一会话和输入框；提供文本、PDF 上传与网址输入入口。
- 消息按照角色和用户区分，角色标识包含头像与文字名称，不能只靠颜色区分；处理中展示明确状态，失败时可查看原因和重试。
- 角色工作摘要可折叠，最终回答与引用清晰可辨。资料卡显示入库状态，不把“已接收”显示成“可检索”。
- 支持长任务结束后在原会话中看到结果；断线重连后从已保存状态恢复展示。

### 6.2 知识库页面

- 提供资料列表、状态筛选、标题或来源搜索、详情、重新处理与删除入口。
- 详情展示原文、来源、时间、处理状态和错误；引用可定位到可用的页面或文本片段。
- 删除前明确确认对象；无法完成清理时显示异常，不把失败隐藏成成功。

## 7. 数据与系统设计约束

以下为需求层设计，具体表结构和接口由技术设计确定。

- **资料与版本**：每份资料有稳定 ID、版本、来源和处理状态；每个文本块指向对应版本及可用位置，引用应能追溯到原文。
- **任务与事件**：每次用户操作和 Agent 工作有任务 ID、会话 ID、角色 ID、时间、状态及结果引用；事件需持久化，以支持刷新恢复和失败排查。
- **索引一致性**：按资料版本进行增量新增、替换、删除；后台任务应具备幂等性，避免重试或并发删除造成旧数据重新进入检索。现有全量同步逻辑在复用前需核查其删除语义，不能直接用单文档数据调用全量同步。
- **能力分层**：对话角色调用受控工具，知识库管理、检索和证据规则由服务端执行。对现有只读 MCP 新增写入能力需单独设计授权与工具边界，不假定现有 MCP 已支持写入。
- **来源安全**：网页抓取限制协议、重定向、文件大小与处理时长，阻止访问本机及内网地址；对上传文件做类型和大小校验。网页与文档内容视为不可信数据，不能作为修改系统规则或执行工具的指令。
- **隐私与部署**：首期为本地可信环境；如启用外部模型或 Embedding 服务，应说明资料可能发送至相应服务。远程访问前必须落实身份认证、访问控制、HTTPS 和资料隔离；现有开发 Web 不得直接暴露公网。
- **可观测性**：记录任务状态、失败原因、耗时和索引版本；避免在常规日志中输出不必要的原文或密钥。

## 8. 验收标准

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| AC-01 | 文本收录 | 粘贴一段有明确事实的文本并要求保存；返回资料卡，状态从处理中变为可检索，列表可查看原文。 |
| AC-02 | PDF 收录 | 上传可提取文本的 PDF；索引完成后可检索到其中内容，引用能展示标题及可用页码。 |
| AC-03 | 网页收录 | 提交可公开访问的网页；保存正文快照、URL 和抓取时间，索引完成后可在回答中引用。 |
| AC-04 | 失败与重试 | 无法访问的网页或无可提取文本的 PDF 显示失败原因，不显示可检索；修正后重试可完成且不重复创建资料。 |
| AC-05 | 新资料问答 | 针对刚收录且已可检索的测试资料提问，回答引用对应资料和可用原文位置；资料不足时明确提示。 |
| AC-06 | 删除 | 用户确认删除指定资料后，新检索不再召回其文本和向量结果；历史引用标记已删除；清理失败可见。 |
| AC-07 | 多角色协作 | 公司比较任务在同一会话展示实际执行的角色、状态、结果及最终引用；失败角色不会显示为成功。 |
| AC-08 | 简单任务 | 单纯收录资料时只展示实际参与的角色，资料处理完成后状态与真实索引状态一致。 |
| AC-09 | 会话恢复 | 刷新或重新进入会话后，可看到已持久化的角色消息、任务状态及最终结果；中断任务状态准确。 |
| AC-10 | 删除与并发 | 处理中的资料被删除后，即使后台任务完成或重试，也不得重新进入检索结果。 |

上线前应使用固定样本验证检索与引用，并补充重复提交、资料更新、索引失败、并行事件乱序、来源冲突和删除后历史引用等测试；不能仅通过界面展示判断功能完成。

## 9. 分期与衡量

| 阶段 | 内容 | 主要成果 |
| --- | --- | --- |
| 第一阶段 | 文本/PDF/公开网页收录，文档管理，增量索引，引用与删除；同会话角色状态与结果展示。 | 完成“收录 → 可检索 → 引用 → 删除”闭环和真实角色协作。 |
| 第二阶段 | 角色配置与投研模板、标签和筛选、主动刷新网页、更多格式。 | 提升组织和个性化能力。 |
| 第三阶段 | 经认证授权的远程访问、移动端入口、更多内容来源和可选的结构化知识抽取。 | 在保证权限和可追溯的前提下支持随时随地使用。 |

建议跟踪：收录成功率、从提交到可检索的耗时分布、处理失败及重试成功率、新增资料相关问题的召回与引用正确率、删除后残留率、任务成功率和用户对角色分工的理解程度。具体目标值应在基线测试后确定。

## 10. 待评审事项

1. 首期运行环境及默认检索配置：关键词索引是否作为最低可用标准，语义检索何时启用。
2. 文件大小、网页抓取时间和资料保留周期的具体限制。
3. 资料更新时历史版本及历史引用保留多久，备份如何清理。
4. 自定义角色首批开放哪些模板和配置字段。
5. 远程部署的身份认证方式、数据存储位置及外部模型服务的使用边界。
