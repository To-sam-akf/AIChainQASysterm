## 1. 本轮实验要回答什么

| 问题 | 对照 | 主要判断依据 | 结论边界 |
|---|---|---|---|
| 接入资料后，回答是否更准确？ | A 直接问模型 vs B 基础 RAG | 要点覆盖、事实支持、严重错误题数 | 检查同一道题的变化；不能仅凭措辞更完整认定准确性提高 |
| 完整 Agent 是否更能完成复杂任务？ | B 基础 RAG vs F 完整系统 | 复杂题可用比例、证据覆盖、要点覆盖及额外耗时和费用 | 衡量完整流程的总体收益，不能归因于某一个检索组件 |
| 证据检查是否减少无依据结论？ | E 关闭答案质量干预 vs F 开启干预 | 无依据陈述、错误拒答、严重错误、任务可用性 | 同时检查收缩回答是否导致关键要点丢失，不能只看错误陈述减少 |

第一轮用 20 题检查出题、生成、独立判分、人工复核和汇总是否配合工作。不预设 F 最优，不设置综合分，也不以少量题目的胜负宣称稳定优势。知识图谱、重排、HyDE、补检各自的贡献留到后续消融实验。

## 2. 比较哪些版本，如何保证公平

### 2.1 版本行为边界

| 版本 | 允许的行为 | 必须隔离的行为 |
|---|---|---|
| A：直接问模型 | 接收问题、统一任务说明和输出要求，调用同一个生成模型 | 不读取知识库、图谱、检索材料或标准答案；不执行规划检索、补检、答案证据检查 |
| B：基础 RAG | 对原问题执行一次原文块向量检索，再根据返回资料生成一次答案 | 不做查询改写、HyDE、混合检索、重排、Claim/Dossier 或图谱检索、Agent 规划、补检、答案证据检查 |
| E：Agent 原始答案 | 保留完整系统的规划、检索、重排和补检，保存生成的原始答案与证据 | 不因最终答案的证据检查结果改写、替换或收缩答案；不执行由该检查触发的后续干预 |
| F：完整系统 | 从 E 保存的同一份原始答案及证据出发，执行答案证据检查；必要时修正或收缩，并保存最终答案 | 不重新独立生成一份原始答案来替代 E/F 配对输入 |

E 保留检索阶段的覆盖检查和证据筛选；它关闭的是最终答案生成后的质量干预。E/F 共享的输入包括问题、规划结果、检索材料、最终采用证据和原始答案，使用同一个配对标识并保存内容哈希。F 如需追加调用或检索，记录为检查触发的增量步骤，不回写 E 的输出。

每题产生 A/B/E/F 四份输出，共 80 份基础输出；E/F 共享生成阶段，因此四份输出不等于四次独立生成。关闭 Agent 的环境变量不构成 B 或 E 的合格实现，后续必须核对实际调用记录。

### 2.2 统一条件与冻结规则

- 同一批题使用相同生成模型与服务端模型标识、温度、思考开关与强度、输出预算、任务说明和输出结构。版本专用提示只表达其资料使用方式，保留提示版本与实际发送参数。服务不支持的参数记录为不支持，运行时降级也要记录。
- 每题从空对话开始，不读取上一题的历史、记忆或答案缓存；各版本独立保存检索状态，E/F 的共享阶段除外。禁止联网补充资料。
- B/E/F 使用同一冻结知识库来源范围。F/E 可使用该快照派生的 Claim、Dossier 和图谱，B 只使用原文块；这些表示层差异属于完整系统的总体能力差异。
- 最终输入生成器的资料采用同一字符预算：计入正文、证据卡文本及来源标识，排除问题和公共任务说明；按各版本确定后的证据顺序截断，记录截断前后长度和实际内容。具体数值在第三步实现时统一冻结，正式运行中不得按版本调整；A 的资料长度为 0。
- 仅将问题与统一公开任务要求传入系统。标准事实、要点、证据单元、拒答标签及候选题中的公司过滤条件只供评测端使用。系统可从问题自行识别公司，但必须记录其来源。
- 知识库不可用、模型不可用或功能未按配置生效时，记录失败或配置不符；不得静默换成离线模板、其他模型或其他版本并继续作为正式结果。
- 重试上限、超时和缓存策略在运行前统一冻结。保留每次尝试和费用，不挑选最佳答案；人工重新运行生成新的运行标识。

正式运行前冻结模型配置、提示、预算、重试策略、题集、资料和评分版本。任何变更生成新的实验运行，不将不同条件的成绩直接合并。

## 3. 用什么题，以及标准依据是什么

### 3.1 首轮 20 题

| 类别 | 题数 | 任务与验收重点 |
|---|---:|---|
| 简单资料查询 | 5 | 单公司、单主题的公开事实；检查准确性及快速流程是否足够 |
| 公司比较或产业链分析 | 5 | 覆盖多家公司、业务环节或机制；检查漏答、证据覆盖和结论边界 |
| 数字、年份、证据冲突 | 5 | 核对主体、时间、单位和统计口径；冲突材料需说明差异，不能直接混算 |
| 资料不足或应当拒答 | 5 | 区分完整回答、部分回答和拒答，禁止补造未披露数据或过度推导 |

公司比较或产业链分析作为预先定义的复杂题分组，首轮为 5 题；资料不足题为单独分组。数字与冲突题单列报告，不在看到成绩后临时调整分组来放大优势。

### 3.2 每道题必须准备的判分材料

| 内容 | 要求 |
|---|---|
| 题号、类别、问题 | 题号唯一；问题可独立理解，必要的时间要求写在问题中 |
| 必须回答的要点 | 分成可逐项判定的要点，区分关键要点和补充要点 |
| 标准事实与原文位置 | 保存主体、事实、时间、单位、来源报告、页码或章节及可核对摘录；有原文块时保留 chunk id |
| 必需证据与替代材料 | 按事实需求定义证据单元，列出允许替代的来源；同一单元多个命中只算一次 |
| 禁止推导的结论 | 明确哪些排名、因果关系、金额替代或其他推断没有证据支持 |
| 预期回答行为 | 标明完整回答、部分回答或拒答；部分回答列明可回答和不可回答部分 |
| 资料截止日期 | 标明可用来源的最晚公开日期，不使用后来材料修补历史答案 |
| 人工核对状态 | 保存核对者、核对日期、争议与处理记录；未核对的题只能调试，不进入正式结论 |

例：比较两家公司的液冷业务与相关收入，需要分别说明两家业务及收入披露情况。没有分业务收入时，不得用总收入替代，不得自行推算排名；有业务证据但无收入披露时，业务部分应回答，收入部分应说明缺口。

事实标准与证据标准分别判定：A 的事实即使没有随答案提供引用，也可由独立评测对照标准原文判为正确；它不会因此获得检索或引用成绩。对资料不足题，不能以“没有找到”自动认定“没有披露”，预期行为须由人工检查冻结资料后确定。

### 3.3 现有题集的使用方式

- [QA v1](qa_benchmark_v1.jsonl) 有 50 题，覆盖公司比较、产业链、风险、指标和拒答，可作为任务候选池；现有关键词和 Claim 类型不足以替代逐题原文事实核对。
- [RAG v1](rag_retrieval_v1.jsonl) 有 50 题；[RAG v2](rag_retrieval_v2.jsonl) 是其检索标注增强版，属于同一套题的版本，不是新增 50 道独立题。
- 现有 RAG 题中的公司过滤条件不得直接用于新的端到端对照。自动标注、`llm_augmented` 状态及模型置信度不等于人工通过，必须回到原文确认。
- 先整理候选题并按问题意图、主体、时间范围和事实需求去重，再选取上述 20 题。第一步不修改已有题集，不声称已完成 20 题人工核对。
- 流程稳定后扩为 100 题：40 道开发题、60 道独立测试题；本轮试运行题归入开发用途。近似改写、相同事实需求和明显关联任务放在同一组；独立测试题不参与提示、检索或评分调试。

## 4. 怎样独立判分

### 4.1 评分原则

先保存生成结果，再对保存结果独立评分。评分端读取标准事实、原文和实际输出，不能将产品返回的 `verification`、自评分或通过状态直接当作正确答案。产品校验结果只用于分析错误原因。

可核验陈述按最小事实拆分，例如“公司甲在某年液冷收入为某金额”需同时核对公司、业务口径、年份、数值和单位；同一意思的重复表述不重复计数。不同引用指向不同陈述时分别判断支撑关系。数字、单位、年份优先程序核对；分析性结论由固定评审说明辅助判断，再按复核规则处理。

事实判断保留“有支持、与原文矛盾、无依据、待复核”四种状态。指标同时保存分子、已判定分母、待复核数和原始总数。待复核项不自动算对或算错；复核覆盖率为已判定项数除以待判定总项数，未复核完成的成绩必须标为暂定。

### 4.2 核心指标

| 指标 | 计算或判定口径 | 特殊情况 |
|---|---|---|
| 必需证据覆盖 | 命中的必需证据单元数 ÷ 已判定的必需证据单元数；替代材料满足同一单元即可 | 分别报告全部检索材料覆盖和最终采用证据覆盖；A 不适用；无必需单元不适用 |
| 要点覆盖 | 正确回答的必需要点数 ÷ 已判定的必需要点数 | 遗漏和错误均不算命中；部分回答题的边界说明也列为要点 |
| 事实支持率 | 有支持的陈述数 ÷ 已判定的可核验陈述数 | 只按截止日期内的独立原文判定；不因检索或引用存在自动算支持 |
| 无依据陈述率 | 与原文矛盾或无依据的陈述数 ÷ 已判定的可核验陈述数 | 同时分别保留矛盾数、无依据数；无事实陈述时不适用，不能算满分 |
| 引用正确率 | 真正支撑对应陈述的引用配对数 ÷ 已判定的全部引用配对数 | 引用不存在、来源错误或无法支撑该陈述均不算正确；无引用时不适用并记录缺失引用，不算满分 |
| 应拒答却乱答率 | 应拒答部分仍给出无依据实质结论的题数 ÷ 已判定的应拒答题数 | 部分回答题对不可回答部分检查；分母为 0 时不适用 |
| 可以回答却拒答率 | 对可回答关键部分无理由拒答的题数 ÷ 已判定的含可回答部分题数 | 部分回答题对可回答部分检查；分母为 0 时不适用 |
| 任务可用性 | 按下列规则判为可用、需大改或不可用；可用比例为可用题数 ÷ 已判定题数 | 失败题计入分母并判不可用；待复核题另外列数 |
| 严重错误题数 | 含至少一个严重错误的题数 | 同时记录错误条数与类型；待复核项不自动判无严重错误 |

一条引用仅包含存在的证据编号，还不足以判为正确：需要核对该来源是否支撑对应主体、时间、数值及结论。引用缺失单列题数和对应关键要点，不能通过少引或不引来获得表面优势。

### 4.3 可用性与严重错误

- **可用**：关键要点全部正确，满足该题明确要求的证据与引用，资料不足部分有正确边界，无严重错误；只需轻微文字整理即可使用。
- **需大改**：保留了正确且可核验的任务主体，但关键要点遗漏、引用缺失或边界不清，需要重新查证或明显修改后才可使用；出现严重错误时至少降为此档。
- **不可用**：运行失败、无实质任务结果、核心结论错误或编造、主体或关键口径错误使任务结论失效，或无理由拒答导致核心任务未完成。

严重错误包括：弄错公司主体，关键数字、单位、年份或统计口径错误，编造来源或披露，证据不足仍作关键排名或因果结论，使用截止日期后的事实改变结论。最终档位按对任务的实际影响判定，不用平均分掩盖核心结论错误。明确指出未披露并保留可回答部分，不算任务失败。

### 4.4 人工校准、待复核与运行失败

- 评审输入隐藏版本名称和产品校验结果，使用匿名答案标识；E/F 配对关系留在汇总端。评审使用固定模型配置和评分说明，必须输出对应陈述、要点、原文位置及理由。
- 首轮先人工评分 8 份答案：每类任务 2 份、每版本共 2 份，并覆盖 E/F 同题输出。记录人工与模型在要点、事实及可用性上的分歧，修订说明后重新评分这批保存结果；分歧未解决前不将模型评分用于正式产品结论。
- 严重错误候选及所有版本判分分歧全部人工复核。其余答案按类别分层随机抽查 20%，各非空类别至少 1 份，保存抽样种子和清单。仍无法判断的保留待复核及原因。
- 运行失败保留题号、异常、已发生调用和费用，不删除或静默跳过；任务判不可用，预期要点按未完成记 0，适用的必需证据按未找到记 0。没有答案的事实与引用指标不适用，不能解释为“没有幻觉所以表现最好”。
- 比例先逐题计算，再在版本内取适用且已判定题目的均值；任务可用性和拒答指标按上述题数计算。均值旁列出适用题数、失败题数和待复核数，不对缺失项补 0 或补 1。严重错误保留原始题数。

## 5. 记录哪些成本、环境与输出

### 5.1 每题输出与成本

| 记录项 | 要求 |
|---|---|
| 输入与答案 | 保存实际问题、公开任务要求、原始答案、最终答案、运行状态及 E/F 配对标识 |
| 检索与证据 | 保存候选材料、最终采用证据、来源和原文定位、排序、截断及实际送入生成器的资料 |
| 实际执行轨迹 | 记录规划、各路检索、重排、补检、生成、检查及修正是否发生，工具和模型调用参数摘要、结果与异常 |
| 耗时 | 记录逐题从接收问题到最终输出的墙钟耗时、阶段耗时及重试耗时；初始化或建索引耗时单列 |
| 模型用量 | 按调用记录生成、规划、HyDE、重排、修正、embedding 和评审的实际用量；保存服务返回的原始 usage，推理及缓存用量可获取时记录，不重复相加 |
| 费用 | 以实际计费规则计算，记录币种、单价来源、生效日期和缓存等计费类别；缺少用量或价格时为未知，不能记成零 |
| 人工成本 | 单列出题核验、评分和复核工时；不能混作模型调用费用 |

E 的成本为共享阶段的全部成本；F 的成本为共享阶段加检查和干预的增量成本。F 的端到端耗时为共享阶段耗时加其后增量墙钟耗时，不能只记录复用答案后的检查时间。整次实验实际账单对共享调用只计一次，另行展示各版本独立完成任务所需成本。在线生成费用与离线独立评分费用分别汇总。

每版本报告总成本和每道计划题目的平均成本，失败与重试费用计入；费用不完整时展示已知部分及未知调用数，总额标为不完整。耗时展示每题原值及中位数、P90，并区分成功与失败，不以并发任务阶段耗时之和替代墙钟耗时。

### 5.2 可复现记录

每次运行至少保存以下信息，后续实现时与输出一起持久化：

- 协议、题集、评分说明及评分程序版本；题集文件哈希、实际题号清单和数据划分。
- Git 提交、工作区是否有修改及可重建该状态的补丁或源码快照引用，不能只记录提交号。
- 资料快照标识、来源清单及哈希、各报告公开日期和文件哈希；原文块、Claim、Dossier、图谱与 embedding 索引版本。运行时数据库快照也要记录，不能只给本地导入文件版本。
- 模型服务、请求及返回的模型标识、生成参数、提示版本、思考参数与运行时降级；评审模型与生成模型分别记录。不得保存 API key 等凭据。
- 配置与实际生效功能、检索和资料预算、Agent 步数和调用预算、超时重试、并发、缓存与运行顺序；运行起止时间使用带时区时间戳。
- 生成运行标识、独立评分运行标识、原始输出内容哈希、人工复核记录，以及费用定价依据。

### 5.3 最终怎样展示结果

汇总表按 A/B/E/F 分列：要点覆盖、事实支持、无依据陈述、引用正确性及缺失引用、严重错误题数、可用任务比例、失败题数、待复核数、耗时和成本。分别展示全部题、简单题、复杂题、数字与冲突题、资料不足题的结果。

按 A/B、B/F、E/F 输出同题差异：要点和证据覆盖上升为改善；无依据陈述下降为改善；可用性按“不可用 < 需大改 < 可用”比较。每项分别统计改善、持平、退步，质量与成本不合并成一个胜负分。任一侧待复核的该指标记为待比较；任一侧运行失败保留配对和失败标记，按上述任务可用性与完成情况比较，不能删除配对来提高成绩。

错误清单保留“问题 → 输出 → 错误与原文依据 → 原因 → 修改措施 → 重测结果”；尚未修改和重测的项写待处理。原因先分为解析错误、未检索到、筛选丢失、理解或计算错误、无依据结论、工具或任务失败六类。

首轮只报告实际题数和观察到的变化。20 题用于开发与流程校准，不输出独立测试结论；后续使用冻结的独立测试题验证产品收益及代价。

## 6. 现有能力与后续工作

| 现有入口 | 可复用内容 | 本轮必须区分的限制 |
|---|---|---|
| [QA runner](../../aika/eval/runner.py) 与 [run store](../../aika/eval/store.py) | 批量执行、运行记录、题集哈希、代码提交和分类汇总 | 现有生成与评分耦合，记录不足以满足本协议全部复现、成本和独立判分要求 |
| [QA metrics](../../aika/eval/metrics.py) | 作为历史回归与调试参考 | 事实支持等指标使用产品 verification 或启发式结果，不能替代本协议的独立评分，也不能沿用原综合分比较新成绩 |
| [RAG runner](../../aika/eval/rag_runner.py) 与 [RAG metrics](../../aika/eval/rag_metrics.py) | 原文块检索指标、证据单元及未标注队列 | 旧 runner 使用题集过滤条件；与新端到端实验分开。原文块成绩与证据卡重排成绩不能直接混比 |
| [QAEngine](../../aika/qa_engine.py) 与 [Agent runner](../../aika/agent_runner.py) | 当前问答和 Agent 流程 | 固定 QA 流程也调用证据校验并可能替换答案，仅关闭 Agent 不会关闭最终答案干预 |
| [LLM client](../../aika/llm_client.py) | 模型配置及部分响应中的 usage | 需要后续补齐跨阶段汇总、失败与重试用量、费用和实际参数记录；不可将缺失 usage 当成零 |

本说明的验收标准是：三个问题都有明确对照；题目有人工核验要求；指标有分子、分母和异常口径；成本与复现记录可指导实现。第一步不新增业务 API、CLI、配置开关或运行结果，不修改已有题集及评分逻辑。

接下来的实施顺序仍按 [plan.md](../../plan.md)：第二步整理并人工核对 20 题；第三步实现和验证 A/B/E/F；第四步分离生成与独立评分并校准；第五步汇总差异及错误；第六步针对主要错误优化后重测。模型与资料预算等运行参数由第三步统一冻结，本协议不虚构当前环境的实测配置或服务价格。
